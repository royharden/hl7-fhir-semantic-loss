# Limitations and claim boundaries

This is Dirty Mode construction. A Python3.12.13 target run of tests/cli passed 37
builder-authored tests, exercising the CLI through Typer CliRunner. Installed-wheel
entrypoint, Java validation, round trip, study campaign and live models remain unrun.
There are no measured headline results, speed claims, model improvements or validated
clinical conclusions. An HTML report renders supplied records; it does not certify them.

Only original, obviously synthetic developer examples are authored here. They are not
held-out cases, independent expectations, calibration controls or an evaluation set.
Roy-appointed O/H/Q and optional human R, actual-use licensing/admission, truth/compiler,
raw fidelity, calibration and custody seals remain pending. Construction review is B
lineage and never satisfies Q. No human or clinical expert validation is claimed.

The planned study is bounded to ORU^R01 v2.8, base FHIR R4 4.0.1, local codes/units and
synthetic convenience sites. It does not establish real hospital integration quality,
population performance or typical v2.5.1 behavior. Rights and exact file/tool locks must
be admitted before executing the planned instrument. Microsoft B1 compatibility is
unproven; a skip requires runtime evidence, not this document. Generic/paired round-trip
stability cannot by itself establish preservation of source meaning.

Wrong-but-valid and lossy-but-valid must remain separate, use actual Java receipts and
explicit denominators, and retain failed/unsupported cases. Unknown meaning must remain
unknown or abstained. Empty denominators are undefined. Mock/authored records cannot
support model-quality claims, statistical intervals, or measured cost comparisons.

Live dispatch, accounts, keys, spending, network, publication and pushes are disabled in
this construction phase. The USD40 lifetime ceiling is not dispatch approval. Later
activation needs the real admission, role, budget, isolation, runtime and review gates;
public promotion additionally needs Roy's approval.

Mock accounting is simulated and cannot establish provider cost. Only simulated
rulings can be appended by this CLI; actor/freeze/evidence hashes confer no independent
appointment, custody authority or admission. B0/DSL consume the same released dictionary
including derived scalar tables; no automatic conversion or undocumented meaning is
invented for legacy or incomplete dictionaries.
