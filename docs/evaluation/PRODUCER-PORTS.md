# Accepted producer serialization adapter

Legacy producer serialization traced at accepted 0edf825; Round2-017 workflow-provider extensions below reconcile accepted009C producer6a27608bd92a398da8587c17300e40dde57046c7 (Integration018). No producer imports or runtime calls occur in this module. `normalize_producer(payload, producer=..., binding=..., expected_binding_sha256=..., source_files=..., config=...)` consumes an already serialized finite JSON value and returns a detached retained original plus a normalized record. No source/config/dictionary object is rewritten to obtain new ledger identities or attempt permissions.

Binding contains producer (B0/B2/DSL/SITE), config_id, site_id, dictionary_sha256, config_sha256, source_hashes; message producers also require case_id and raw_sha256. expected_binding_sha256 is externally frozen digest(binding). source_files maps declared logical artifact names to their exact byte contents, which must match source_hashes. Config is hashed unchanged; B2/SITE config must include model. Hash comparison does not prove runtime transitive closure or external admission. Runner must separately pin the adapter, producer artifacts, configuration and actual entrypoint and enforce the single lifetime ledger. This module creates no database, authorizes no dispatch and resets no budget.

B0 mapped/partial, B2 produced and DSL ok normalize to completed only when an embedded Bundle and literal source identity agree. B0 native case ID is raw hash first16; DSL native case ID is full raw hash; B2 native ID must equal the explicit scheduled case. Normalized case_id is the external schedule binding and producer_case_id is retained separately. Original producer payload/provenance/attempt IDs are never edited. B2 bundle_sha256 is checked under the exact compact sorted ensure_ascii=True canonical JSON contract; B0/DSL have a locally computed output hash labeled construction only. Producer refused/error remain error, with original outcome/error retained. No error-string interpretation manufactures timeout, Java, RT, billing or semantic success.

All B2/SITE initial/repair/reservation/refusal/dispatch/usage records remain unchanged under producer_result and attempts. Missing usage stays unknown/unreported, never zero. Known usage uses integer microUSD. Usage states follow actual Ledger literals reserved/settled/unknown/liability_breach; not_dispatched does not erase previously_dispatched evidence. Request fingerprints/messages/dictionary/model/config/raw/case/site/repair provenance are checked without rewriting IDs. Provider evidence classes remain their original claimed/unverified labels; other construction outputs remain unverified_construction. All Java/generic/paired statuses default explicitly not_run, semantic flags null.

SITE returns record_kind=site_setup and setup_produced/setup_failed with proposal/hash/attempts. It never becomes a scored message or produces a Bundle. The separate site/config/dictionary identity is checked against proposal and every reservation provenance. `denominator_records(normalized, final_attempt_id=...)` refuses site setup or unsupported binding, returns one campaign attempt and an unmeasured assessment for a bound message only, preserving all nested producer attempts/usage. Campaign attempt ID must be predeclared by the runner and never replaces the nested producer/ledger IDs. Site proposal records must be retained and hashed as separate setup artifacts before message freeze; the current runner message schedule does not dispatch site setup.

Unrecognized/malformed/binding-drift finite JSON produces outcome=unsupported with the full original retained, binding_verified=false and no denominator attribution. This can remain in frozen runner evidence; the scheduled case remains missing/unmeasured until separately reconciled. It never triggers a replacement call. Non-JSON/nonfinite input is outside this serialized boundary and raises; callers must retain original raw artifacts rather than discard evidence. No complete scorer or independent truth is introduced.
