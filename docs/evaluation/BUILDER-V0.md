# Builder-v0 provisional assertion policy

**Builder-authored, provisional, not independent gold.** Canonical policy is schemas/builder-v0-output-policy.json; evaluation.builder_v0 consumes it. Ratification remains PENDING - Roy. Every result sets complete_semantic_score=false and headline_eligible=false. These developer tests/expectations are not oracle calibration, independent evaluation, held-out data or clinical truth.

The original policy is an occurrence projection: exclude only Bundle resourceType/type, entry fullUrl and resource resourceType/id as metadata/identity. Every other scalar or empty container is an assertion, including unlisted output fields; coding displays and texts are not silently excluded. Resource types Patient/DiagnosticReport/Observation/ServiceRequest are the bounded supported set; other types remain explicit issues and their content is retained. Assertions have subject, role, kind, value and exact escaped JSON pointer. Array indices are removed from roles but remain in pointers, preserving repeated occurrences.

A reference leaf is a directed relation. Local resourceType/id and fullUrl aliases resolve only to one local target; duplicate aliases and dangling targets never match. This is an original developer convention, not a normative FHIR or clinical relationship rule. Explicit expected relation cardinality min/max is a separate condition finding, never inferred from schema conventions or prose. Assertion errors and cardinality conditions can describe the same edge and must not be summed as unique clinical errors.

compare(bundle, expectations) consumes an explicit developer expectation document: policy_id=builder-v0, exact authorship label, assertions list, relation_cardinalities list and unmatched_critical boolean. Each assertion has subject/role/kind/allowed_values/critical and represents exactly one occurrence. Explicit allowed values are the only equivalences. Maximum bipartite matching prevents overlapping alternatives from creating greedy mismatches. Remaining same-role scalar values are distortions; relation values are wrong_relation; unmatched expected rows are missing_assertion/missing_relation. Excess matched-value repetitions are duplicates; other excess admitted alternatives are alternative_stuffing; other leaves are inventions. Critical status is an explicit builder hypothesis, never a clinical designation. Duplicate/alternative findings retain occurrence paths. No comparison compiles truth from raw HL7, mutates a source corpus, or supplies an independent compiler/renderer/checker.

This projection does not establish complete semantic coverage, expected-source fidelity, source obligations/disposition honesty, actual Java validity, generic/paired RT correctness, independent O/Q agreement or real-model quality. Bounds are 1024 resources, 100000 traversed nodes, depth64, 2MB serialized input and512 occurrences per matching role. Runtime security/isolation is separate. Future O/Q may replace or ratify the versioned policy and must supply independent references before any complete score/headline/campaign claim.

Round2 developer-only validation covers exact/distorted/missing/invented leaves, duplicate and legitimate repeated occurrences, alternative stuffing/overlap, wrong/dangling/ambiguous relations, cardinality conditions, explicit metadata, strict scalar equality and refusal bounds. No external standards files or assets are embedded.
